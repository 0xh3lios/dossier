# Commands and skills

The `dossier` command compiles the prose, draws the chart, runs the trials and rebuilds the ledgers. The skills call it.

## The command

`dossier` is `bin/dossier` in the plugin. Claude Code puts it on the session's PATH while the plugin is enabled. In ChatGPT and Codex the skills run it by its path in the plugin's folder.

To run it in your own terminal, add the plugin's `bin` folder to your PATH, or link `bin/dossier` into a folder already on it. The `plugin` line of `dossier doctor`, which the agent can run for you, names the plugin's folder. A checkout of this repository works the same way:

```bash
export PATH="/path/to/dossier/bin:$PATH"
```

| Command | Does |
| --- | --- |
| `dossier verify [--brief] [--json] [<dossier>...]` | Analyzes without writing or repairing any file. Prints the verify line, summaries, next steps and findings. Naming dossiers limits what it prints, never what it analyzes. `--brief` prints dossiers whose next step is not `Report` or that are named. `--json` prints the findings as JSON. |
| `dossier render [--brief] [--json] [<dossier>...]` | Writes the ledgers and the root's `index.md` from the same analysis. It records no evidence and does not regenerate composition models. The ledgers and the index are views, and deleting one changes no conclusion. The `.gitignore` that setup writes keeps the index out of git. |
| `dossier recover <dossier> trial <id> [--dry-run]` | Finishes an interrupted answer publication from what waits in `.running/<id>/`. A candidate entry the manifest already binds is renamed into place, and the entries that publication dropped are deleted, as its list names them. A candidate it does not bind is discarded, and the bundle's answer goes through publication again under the [evidence rules](files.md#evidence), once, as if its trial had just ended. So does a bundle that waits without a candidate. Never replaces an entry that differs from its binding, and preserves pending calls. |
| `dossier recover <dossier> decisions [--dry-run \| --confirm <suffix-sha256>]` | Shows a pending decision suffix and its SHA-256. Confirmation publishes exactly those inspected words, provided the suffix is still the same single valid decision. |
| `dossier recover <dossier> lock [--dry-run]` or `dossier recover --root-lock [--dry-run]` | Inspects a publication lock and explicitly recovers only a demonstrably dead local owner. `--root-lock` names the root's lock, which setup, `begin` and `import` take. Never steals a live or foreign lock based on its age. |
| `dossier draw <part> [--brief] [--json] [--limit <n>]` | Compiles the prose, writes the chart's files and runs the chart's checks. Records no evidence. `--brief` prints the summary's first line only. The limit on explored states defaults to 20000, and an exploration that exceeds it fails with `exploration exceeded <n> states`. |
| `dossier scaffold <part\|composition>` | Writes a part's TLA+ scaffold, or regenerates a composition's module and its configurations, one per cell and one per walk. A part that already has its module gets a fresh `<Id>.scaffold.tla` beside it. It refuses prose that does not compile, and a part with no State passage, and then writes nothing. |
| `dossier call <dossier> <name> <kind> [<target>] [options]` | Writes `calls/<name>.md` with the lines that identify the question: the kind, the files the trial executes, the cell or walk, Apalache's mode, invariant and constant initialization, a blunder's `base:`, and one `expect:` line for each name the configuration enables, or for the Alloy command, the invariant, the prose's walks or the chart's `checks`. The target is the walk or property of a `tlc` call, the property of an `apalache` call, the `.als` of an `alloy` call or the copy of a `blunder`. A composition call takes `--scenario`; a walk's defaults to its own. `--inv` names another invariant than `Inv_<property>`, `--mode bounded` with `--length` asks for a bounded check, and `--base` names a blunder's base. The prediction comes from `--reach`, `--expect "<name>: <outcome>"`, once per name, `--because`, `--blunder`, `--trace-data` and `--runner`, or is left for the agent to fill in. The command prints the file it wrote and the lines still empty. An outcome left out is written as `<name>:` with nothing after it, which the runner refuses until it is filled in. It refuses a name the configuration does not enable, an outcome the runner does not read, a composition cell without its scenario, and an existing call file unless `--force`. |
| `dossier blunder <dossier> <copy> --replace <text> --with <text> --wrong "<words>" [--property <id>] [--scenario <id>] [--base <module>] [--all] [--reach <words>] [--because <words>] [--force]` | Copies the part's module, or the one `--base` names, to `model/blunders/<copy>.tla` with its MODULE line renamed, and replaces the text once. It refuses text the module lacks, and text it holds more than once unless `--all`. Beside the copy it writes `<copy>_<property>.cfg`: the module's configuration that enables the property, or for a composition the cell's generated configuration, with only that property enabled. It then writes `calls/blunder-<copy>.md` as `dossier call` does, with `blunder: <words>` and the property expected `violated`. A composition blunder takes `--scenario`. With `--base <Module>.als` it copies an Alloy model to `model/blunders/<copy>.als`, and its one check is the property. It refuses an existing copy or call unless `--force`. |
| `dossier trial <dossier> <call.md> [--timeout <seconds>] [--workers <n>] [--limit <n>]` | Plans and runs one call against private copies of its inputs, and prepares generated composition inputs there. Records their identities, leaves the trial's bundle in the local `trials/<id>/`, and passes its answer to publication, which writes it to the question's entry under `evidence/`, keeps the entry or refuses the answer, by the [evidence rules](files.md#evidence). A trial that gives the recorded answer again, while that answer has not lapsed, keeps the entry as it is. A publication that keeps the entry or refuses the answer says why, and one that is not refused also removes the entries of gone questions and superseded answers. It looks for the call in `calls/`, then the working directory, then the dossier, and consumes a call in `calls/` only if its bytes still match the captured call. Timeout defaults to 600 seconds, TLC workers to 1, and chart exploration to 20000 states. A composition call names a property or walk and its scenario. Invalid calls and unavailable checkers are refused before execution. |
| `dossier recheck [<dossier>...] [--timeout <seconds>] [--workers <n>] [--limit <n>]` | Asks again the question of every entry whose answer has not lapsed, at the entry's recorded reach, in a private workspace. It takes the trial command's options. It compares the verdict, the outcomes and the reach with the entry's. With dossiers named, it rechecks only those. It writes nothing, consumes no call, and exits 1 on any difference. Each entry gets one line, `same:`, `different:` with the recorded answer beside the new one, or `not run:` with why. An entry is not run when its answer has lapsed, is aborted or is superseded, when its question is gone, or when its call no longer runs here, such as one for an external runner that `dossier.json` does not configure. A dossier whose records, or whose members' records, do not verify is named once, and none of its entries runs. Its last line is the summary, `recheck: <n> same, <n> different, <n> not run`. It needs the toolchain the answers came from. |
| `dossier show <dossier> <entry> [--json]` | Prints the answer that `evidence/<entry>.json` records: the question in one line, the verdict, the outcomes beside the call's, the reach, and the trace as a table of states. Each row holds the state's index, its action and the values that changed from the state before, and the first row holds every value. A TLC trace ends with its loop when it has one. An Apalache trace has no actions. `--json` prints the entry as it is. It writes nothing. |
| `dossier decide <dossier> <verb> ... -- "<words>"` | Records a decision: `begin [charted\|modeled\|composition]`, `accept <ids>`, `reject <id>`, `answer D<n> a\|b`, `risk <property> <scenario>`, `forget <name>@<digest>`, `retire`. `begin` writes a new part's `prose.md`, with `Module: <id>`, or a new composition's `wiring.md` and `prose.md`. On a folder of hand-drafted inputs that holds no `integrity.json`, no `decisions.log` and nothing in `evidence/`, `begin` writes an empty `integrity.json` and records the begin. It refuses a folder that holds a `decisions.log` or entries without `integrity.json`. `risk` refuses a cell that is not violated now, and its line names the trial that established the cell's deciding answer. `forget` names an entry by its file name in `evidence/` without `.json` and the first eight hex digits of the digest `integrity.json` binds for it. [Record a decision](../how-to/record-a-decision.md) says what each verb does. |
| `dossier where <ref>` | Says what a part, composition, property, scenario, actor or record touches. A dossier is named by its id, or by its path, such as `compositions/control`, which names that dossier alone. A property is named by its id, or as `<composition>#<property>`. For a part it also lists the events it sends into other parts, and the compositions that leave them free. For a composition it prints its members with their roles, its properties, its default scenarios, its cells, its wiring and its free sends. For a retired part or composition it says so, such as `part <id>: retired`. For a scenario it prints each actor's mode, with its window when it has one, such as `lane-a offline from 0 until 2`, and the start. For an actor it prints the pins. For a record it prints what pins it, such as `pinned by member timelock of composition control`, and the guarantees it backs, such as `backs adapter K1`. |
| `dossier explore [--install] [--port <n>] [--limit <n>]` | Serves the explorer, a page over the root, at `http://127.0.0.1:<port>/` until it is stopped. The port defaults to 3677, and the next free one of the following twenty is taken when it is busy. It reads and never writes. Marks, cells, flags and next steps come from the analysis verify makes. A part's chart, its walks and what each event does at a state come from the chart's run, as draw runs it, with the limit on explored states `--limit` sets, 20000 by default. A change under the root, or in the knowledge base that `dossier.json` names, refreshes an open page; changes in `.explorer/`, `node_modules/`, `_scratch/`, `.git/` and each dossier's `trials/` do not. It answers only GET requests, only on 127.0.0.1, and only to a page opened at that address. `--install` builds the page into the root's `.explorer/`, from the packages the plugin pins, which it downloads from the npm registry and removes once the page is built, and exits. A failed build removes what it made. The folder ignores itself. Without a current page, explore says how to build it and exits 1. [Open the explorer](../how-to/open-the-explorer.md) shows what the page holds. |
| `dossier import <module> [--as <part>]` | Drafts a part from the knowledge base's records, and prints the senders to declare in `actors.md` or to start parts for. Each drafted event names its sender by the actor record's name as written, such as `the Keeper lane A`, or by the record's id. A quantity becomes a datum only when its id, with hyphens as underscores, is a data name. |
| `dossier doctor` | Says what the toolchain has and lacks. |
| `dossier setup [--knowledge <path>] [--install] [--dir <path>]` | Prepares `dossiers/` in the working directory or under `--dir`. `--root` names the dossiers folder itself. A new root's marker says `storage: integrity-v1`. Setup validates and updates the marker under the root lock. It adds `storage: integrity-v1` to a marker that names none while no dossier exists under the root, and refuses a malformed marker or one that names no storage over existing dossiers. An external knowledge path is stored as an absolute, machine-specific path. Setup writes a `.gitignore` that keeps the index, each dossier's `trials/` and `.running/`, `_scratch/` and `node_modules/` out of git, and leaves one that is already there. `--install` installs the chart libraries. A nondefault root is recorded in the project's `.dossier-root`. Commit that pointer. Setup then runs doctor, reads the fixture as a smoke test and verifies this root without writing reports. It creates no part or composition dossier. |
| `dossier version` | Prints the plugin's version. |

`call`, `blunder` and `show` are helpers the agent may do without. The runner accepts a call or a blunder written by hand as it accepts theirs, and `show` prints what the entry's JSON already holds.

Every command takes `--root <path>` to name the dossiers root. Otherwise it uses `DOSSIER_ROOT`, or the nearest folder at or above the working directory that holds `dossier.json`, holds `dossiers/dossier.json`, or keeps a `.dossier-root` naming the root. A `--root`, a `DOSSIER_ROOT` or a `.dossier-root` that names a folder with no `dossier.json` stops the command with `dossier: no dossier.json in <path>`. Setup is the exception, since it prepares that folder. So is the doctor, which lists the root as missing and exits 1.

`<dossier>` is a bare id, `parts/<id>` or `compositions/<id>`. A bare id names the part with that id, or the composition when no part has it. [Files](files.md#layout) gives the form of an id.

`--timeout`, `--workers` and `--limit` take whole numbers above 0, and `--workers` also takes `auto`. Any other value stops the command before anything runs. Trial, draw, scaffold, call and blunder refuse a retired dossier with `dossier <command>: <ref> is retired; dossier decide <ref> begin reopens it`.

### Storage and recovery

`dossier.json` must say `storage: integrity-v1`. It is the only storage format. A marker that names no storage, or another one, fails verify. `trial`, `decide`, `import` and `recover` refuse that root with exit 2 and a message such as `dossier decide: dossier.json names no storage; this plugin reads integrity-v1 only; no evidence or decision is published to a root in another format`. Only lock recovery still runs there. Restore a lost or damaged `dossier.json` or `integrity.json` from version control, and never recreate it from what survives.

Verification reports incomplete publications and leaves them untouched. Recover a dead writer's lock before retrying its publication. For an answer, `dossier recover <dossier> trial <id>` finishes the publication from what waits in `.running/<id>/`. For a decision, inspect `dossier recover <dossier> decisions --dry-run`, then supply the displayed digest with `--confirm`. A malformed recovery guard requires inspection with all writers stopped. The [storage contract](../../spec/storage.md) defines the authority and the recovery limits.

### Exit codes

| Code | Means |
| --- | --- |
| 0 | Done. For a trial, the answer is as called. |
| 1 | Verify found a tripwire. Draw's checks failed, the prose did not compile, the exploration exceeded its limit, or `xstate` is not installed. Scaffold found a part that does not compile, a part with parallel regions, or a composition that does not compose. A trial was miscalled. Recheck found an answer that came back different. Decide refused because the dossier has a tripwire. Doctor found something missing, a `--root` without `dossier.json` among them. Explore found no page built, or one built from other sources, or no free port, or `--install` could not build one. Where found nothing that names the reference. Import found a `prose.md` already in place. Setup's smoke test or its verify found a tripwire. Show found an entry that does not parse. |
| 2 | A usage error or invalid option, missing root, refused trial, call, blunder or decision, an entry that show does not find, a root that does not name `integrity-v1` storage, or refused recovery. Also a retired dossier given to trial, draw, scaffold, call, blunder or an ordinary decision, and import without a configured module. |
| 3 | A trial aborted: its checker started and did not finish. Also a trial whose publication did not finish, which waits in `.running/` for explicit recovery, and a trial whose private input copies changed while it ran. That trial publishes nothing, and its call stays pending. |
| 4 | An internal error. The command prints `dossier: internal error: <message>`, and the stack too when `DOSSIER_DEBUG` is set. |

When `npm install` fails under `setup --install`, setup returns npm's exit status.

## Skills

A skill is invoked by name. In Claude Code that is `/dossier:<skill>`, such as `/dossier:setup`. In ChatGPT you choose a skill with `@`, and in the Codex CLI you mention it with `$`. The agent also picks `keep`, `setup` and `review` on its own when a request fits them. `decide` runs only when you invoke it.

| Skill | Use |
| --- | --- |
| `keep` | The agent's hub. It loads when you start a dossier, ask to check or prove a claim, ask a what-if, accept something, or ask where things stand. |
| `setup` | Prepares a repository: runs setup, asks before installing anything, and offers to let the `dossier` command run without a prompt. |
| `review <dossier>` | An independent second read in a fresh context, by a reviewer that reads the dossier's files and writes only its review, `reviews/<date>-review.md`. |
| `decide <dossier> <verb> ... -- "<words>"` | Records a decision with your words untouched. Only you can invoke it. |
| `explore [<part\|composition>]` | Builds the explorer's page once, after asking, starts `dossier explore` and gives you the address. |

## Environment

| Variable | Used for |
| --- | --- |
| `JAVA`, `TLA_TOOLS`, `APALACHE`, `ALLOY_JAR` | The solvers. See [Toolchain](toolchain.md). |
| `DOSSIER_ROOT` | The dossiers root, when `--root` is not given. An external runner receives it too. |
| `DOSSIER_EVIDENCE_STORE` | A folder that keeps a checker's whole output when it is over 512 KiB, as `<sha256>.txt`. Without it, the bundle's `output.txt` is cut at 512 KiB. |
| `DOSSIER_DEBUG` | Prints the stack of an internal error. |
