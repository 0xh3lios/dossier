# Implementation status

The `dossier` command reads behavior collections and scoped reviews, derives each claim's report, and checks, during answer publication, the mappings that depend on the answers it would replace or remove. It accepts only the [record formats](artifacts.md#record-formats) and the root version that [storage](storage.md#format-and-authority) names. It converts no earlier format and falls back to none. An answer keeps the version of the tool that produced it.

| Area | Mechanism | Limit |
| --- | --- | --- |
| Collections and behaviors | The reader checks the fields, ids, paths, scope and mapping targets | A valid file may still explain the system wrongly |
| Claim standing | Verify reads the current answers, the scope's pins, the evidence that conflicts and the independent assessments | A mapping is interpretation and adds no evidence. A result about the model establishes no correspondence to the source |
| Independent review | Verify checks that every file the subject requires is bound, the declared digests, each subject claim's digest, the coverage, the assessment of each mapping and the explicit replacements | A review of one behavior cannot clear the review a dossier owes. A digest does not authenticate the reviewer or establish that the judgment is sound |
| Review preparation | `dossier review-basis` prints the required basis as it stands and the coverage items, and writes nothing | The reviewer must read the material, name what else the judgment depends on and write the assessment |
| Evidence publication | Before it replaces or removes an answer, publication looks through the root for the mappings that depend on it, and checks that no dossier or knowledge input changed meanwhile. Verify does not report an answer a mapping holds by its exact question as superseded | Equivalence of scope is judged conservatively. When equivalent support cannot be established, the entry stays or the replacement is refused. A new counterexample can still be published under the ordinary answer rules. Publication refuses a symbolic link under an authored `chart/blunders/` or at its `chart/` directory |
| Initialization | `begin` and `import` create the collection's `README.md` and the `behaviors/` directory when they are absent | The first collection is empty. An agent writes its orientation, claims and mappings |
| Reader output | `dossier verify --json`, the rendered ledgers and the explorer share one derived behavior report | Nothing holds a status to edit, a verified badge for a whole collection or an automatic claim that the source is covered |
| Navigation | The explorer opens with the orientation and the behaviors in order, keeps a walk under the claims it is attached to, and shows apart what in the model no behavior names | A walk with no behavior is not for that reason unfinished. Exploring the chart publishes no evidence |

The [conformance checks](conformance.md) keep apart the checks of form, the derivation of evidence, retention, independent interpretation and the exercises of the readers. A type check and a unit test do not establish that the abstraction is faithful or that the source is explained in full. Release qualification also checks real solver execution, independent reviews and the interfaces that read the report. Those results belong to the release's record. The format alone guarantees none of them.
